# 有序 · 工作任务管理

使用原生 HTML、CSS、JavaScript 的中文任务管理网页。无第三方运行依赖、密钥或付费服务。初始任务与负责人均为虚构。

## 使用方法

直接双击根目录的 `index.html` 即可使用。推荐通过 GitHub Pages 访问，获得稳定的浏览器存储来源。也可在已安装 Python 的电脑上，在仓库目录运行：

```sh
python3 -m http.server 8000
```

然后在浏览器打开 `http://localhost:8000`。无需 Node.js 或 npm。

点击“新建任务”，填写标题、负责人、截止日期及状态，然后保存。通过“编辑”修改，通过“删除”并确认移除任务。搜索框匹配标题和负责人，可与状态筛选一起使用。顶部统计始终统计全部任务。

## 初学者验收步骤

1. 首次打开网页，确认显示 5 项任务、2 项进行中、1 项已完成。
2. 新建“测试任务”，负责人填“测试员”，任选截止日期和“未开始”，保存后总数应为 6。
3. 编辑测试任务，改为“进行中”，确认进行中数量变为 3。
4. 搜索“测试员”，应只显示测试任务；再筛选“已完成”，应出现无匹配提示。
5. 清空搜索并选择“全部状态”，刷新网页，确认修改后的任务仍在。
6. 点击删除，先取消，任务应保留；再次删除并确认，任务应消失且统计更新。
7. 缩窄窗口或用手机访问，确认按钮、筛选和弹窗均可操作，页面无横向溢出。

## GitHub Pages 发布

1. 将文件变更提交并推送到仓库 `main` 分支，也可先创建 Pull Request，检查后合并。
2. 在 GitHub 仓库打开 **Settings → Pages**。
3. 在 **Build and deployment** 中选择 **Deploy from a branch**。
4. 分支选择 **main**，文件夹选择 **/ (root)**，点击 **Save**。
5. 等待部署完成，打开 Pages 设置页提供的网站地址，通常为 `https://linkinandy.github.io/my-first-web/`。
6. 按上方步骤验收。更新后若显示旧内容，可强制刷新浏览器。

如看不到 Pages 设置，请确认拥有仓库管理权限，且仓库可见性及 GitHub 套餐支持 Pages。资源使用相对路径，支持仓库子路径部署。

## 数据与局限性

- 数据仅保存在当前浏览器、当前站点的 `localStorage`，不上传服务器，不能跨设备或多人同步。
- 删除全部任务后刷新不会重新生成演示数据。清除站点存储后，下次访问会重新初始化演示任务。
- 清除浏览数据、使用无痕模式或更换浏览器、网址、端口后，数据可能丢失或无法共享。目前没有导入、导出、备份功能，请勿将其作为重要任务的唯一记录。
- 直接打开本地文件时，存储行为因浏览器而异；正式使用推荐 GitHub Pages 或本地 HTTP 服务。
- 保存失败会提示，操作不会被标记为已保存。损坏数据不会被自动覆盖，页面会暂停修改以保护原数据。
- 不支持多标签页实时同步，同时编辑可能互相覆盖，建议只在一个标签页中操作。
- 不含登录、权限、提醒或附件功能，请勿记录敏感信息。
- 推荐近期版本 Chrome、Edge、Firefox 或 Safari，需要启用 JavaScript 和站点存储。

## 文件与开发验证

- `index.html`：页面结构与任务弹窗。
- `styles.css`：桌面与手机布局。
- `app.js`：任务操作、校验、筛选、统计与存储。
- `tests/test_browser.py`：可选浏览器回归测试，不属于网页运行依赖。

当前环境已有 Python Playwright 和系统 Chromium，运行：

```sh
python3 tests/test_browser.py
```

测试自带临时 HTTP 服务，使用隔离的浏览器数据，不修改真实任务。若换到其他测试环境，需要先安装 Playwright 与 Chromium，并调整测试中的浏览器路径。GitHub Pages 发布只需要根目录三个网页文件，不需要安装测试工具。

本次 Chromium 的 10 项回归检查通过，包括增删改、筛选、持久化、320–1440px 布局和存储异常保护。`git diff --check` 通过。当前云浏览器策略禁止访问 `file://`，因此直接双击文件的方式未在此环境完成验证；HTTP 访问已验证。尚未实际部署到 GitHub Pages，也未验证其他浏览器。
